# Phase 3 预注册设计：检测时机、可撤销更新与任务成功

本文件在第三阶段数据生成、策略编码和正式测试之前写入。项目管理门槛是本项目的预注册决策规则，不是普适统计定律。

## 1. 第二阶段实现审计

### 检测器

- Method C（`phase2/src/detectors.py:74`）用前三会话建立参考目标。之后逐会话计算当前主导目标与参考目标的证据差；单次强证据或连续达到阈值即报警。它只返回首次报警，较弱的候选状态不对外暴露。
- Method D（`phase2/src/detectors.py:93`）同样只读按时间排序的会话文本。它维护快速指数状态和有限投票窗口；达到确认票数后才返回 `detected_at`，同时把第一个候选票位置作为 `estimated_onset`。`estimated_onset` 是确认时才可获得的回溯字段，不能用于更早在线更新。
- 两者输入均为 `session_id/text`；公开预测函数不接收场景、真实起点或标签。

### 记忆更新与任务调用链

`generate/load observable prefix -> detector prediction -> extract_memories(prefix) -> apply_strategy -> score_task -> label-side evaluation`。

- 原始漂移感知策略仅在 `detected_at <= 当前时点` 后生效；用最近两会话推断目标，只降权报警前的冲突长期目标。
- 改进策略始终先降权显式临时意图/历史计划；报警后用可调回看窗口推断目标，对全部冲突长期目标正式降权或标记待确认。背景记忆不降权。
- 任务评分器只接收当前任务要求、策略实际记忆状态和稳定背景要求；它不以策略名称决定成功。
- 第二阶段任务均用任务时点前缀，不读取未来会话；阈值在完整开发轨迹上选择；Bootstrap 以完整轨迹为单位。第二阶段测试已被查看，只能用于本阶段探索性消融。

### 可替换性

记忆函数消费普通检测字典而非检测器名称，因此以下 2×2 消融语义成立：

| ID | 检测器 | 记忆策略 | 解释 |
|---|---|---|---|
| A | Method C | 原始 | 第二阶段原始基线 |
| B | Method C | 改进 | 固定较早检测，隔离记忆策略变化 |
| C | Method D | 原始 | 固定原始记忆，隔离检测延迟变化 |
| D | Method D | 改进 | 第二阶段当前改进方案 |

## 2. 待验证机制

- H1：D 的任务下降主要来自确认更晚，使确认点附近任务仍受旧目标干扰。
- H2：短暂变化触发正式更新后，如不能撤销，会造成恢复后的任务失败。
- H3：过时记忆分类 F1 不是任务成功的充分条件；在线时机、背景保护和恢复状态同样重要。

消融能提供机制证据，但合成数据不能建立对真实 Agent 的外部因果结论。

## 3. 新候选：Early Reversible

Method D 内部存在因果候选票，但第二阶段没有公开。第三阶段新增独立在线状态机，每个时点只处理当前及历史文本：

1. **候选状态**：当前目标相对初始参考的指数证据差达到开发集选择的 `candidate_margin`，立即把冲突长期目标临时降至 `pending_weight`；背景不变。
2. **确认状态**：有限窗口内候选票达到 `confirmations`，把冲突长期目标正式降至 0.10。
3. **恢复状态**：观察到初始参考目标连续 `recovery_votes` 次占优时，撤销该候选/确认周期造成的目标降权。
4. **超时**：候选后连续 `timeout` 个无候选会话，撤销临时降权。
5. **范围保护**：显式临时意图与历史计划固定降至 0.25；稳定背景固定为 1.0。状态机不读取真实漂移标签。

参数只允许从配置中的网格在开发集选择。选择目标预先规定为：任务成功率 − 0.25×旧目标冲突率 − 0.10×恢复失败率，同时要求开发集背景保留率不低于 0.98。

Oracle Timing 使用真实漂移起点立即正式降权，仅作为不可部署的时机上界，单独报告且不参与正常方法排名或继续门槛。

## 4. 独立数据与锁定

- 新种子 `20270417`；七场景各 16 条开发、32 条测试，共 112/224 条完整轨迹。
- 会话数 12--17；漂移位置、渐进长度、临时持续长度、证据缺失、目标反复、噪声和表达变体按配置固定范围抽样。
- 交互与标签分文件。数据生成后先写 SHA-256 锁定清单，再运行开发集选择和正式测试。
- 测试集不用于阈值或策略选择。若实现缺陷迫使测试重跑，必须在报告披露。

## 5. 评价协议

主要确认指标：Early Reversible 相对 D 的轨迹级任务成功率差。

- 检测：Precision、Recall、F1、FPR、±2 定位命中率、绝对定位误差、延迟及七场景分组；无漂移延迟为 NA。
- 记忆：过时记忆 P/R/F1、干扰率、有效背景保留、错误降权、短暂变化恢复成功率。
- 任务：成功率、旧目标冲突、背景保留、首次正确执行新目标时间，以及按失败机制计数。
- 统计：完整轨迹 Bootstrap 3000 次；主要策略配对随机化检验 20000 次；多重比较用 Holm 校正。

## 6. 继续/停止标准

Early Reversible 必须同时满足：

1. 相对 D 的任务成功率至少提高 0.05；
2. 配对 95% CI 下界大于 0；
3. 背景保留率至少 0.98；
4. 稳定场景成功率相对 D 下降不超过 0.02；
5. 短暂变化恢复结果单独审查，不得以总体均值掩盖恢复失败。

未满足则结论为“不继续当前实现”或“证据不足”，不会降低门槛。即使满足，也只支持继续受控研究，不代表真实 Agent 有效。

## 7. 单元测试与完整性

新增策略测试覆盖：持续漂移、短暂变化并恢复、候选误报超时、漏报无更新、背景保护。运行前后比较第一阶段 18 文件的可靠快照；第二阶段 manifest 覆盖结果产物，但未覆盖全部源码/数据，因此第三阶段运行前另建完整 SHA-256 基线并在结束时复核，此限制不会伪装成已有历史签名。
