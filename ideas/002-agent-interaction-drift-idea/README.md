## 2. 一句话摘要

在多 agent 协作/对话场景中，先建立一套可稳定标注的**语义原子本体**（role / goal-atom / tool-action / commitment / constraint），再用它逐轮探测 agent **之间**是否发生语义层漂移——即回答「agent 交互中到底有没有漂移、有多显著、能不能在发生的那一步被检出」。

## 3. 问题与背景

- **科研问题**：多 agent 系统（CAMEL / AutoGen / MetaGPT / ChatDev 等）已被广泛使用，但**agent 之间**在协作过程中偏离初始目标/角色/约束的现象，目前只有 post-hoc 的行为指标，缺少**逐轮、在线、可定位**的检测手段。
- **为什么现在值得研究**：
  1. 多 agent 系统正从 demo 走向生产，失败代价上升；
  2. 已有工作刚把"失败模式"命名完（MAST, NeurIPS 2025），但**度量层仍停留在事后聚合**，逐轮定位是空的；
  3. 本组已有 DriftHunter 的"跨轮转移累积"技术积累，具备方法基础。
- **已知方法的不足**：
  | 方法族 | 代表 | 不足 |
  |---|---|---|
  | 行为指标（post-hoc） | role adherence、ASI 类复合分 | 是漂移**后果**的滞后聚合，**无法对齐到轮次** |
  | 拓扑/谱分析 | Spectral Dynamics (`2607.22758`) | 矩阵建在**通信拓扑图**上，不是语义状态，无逐轮语义信号 |
  | 失败模式标注 | MAST (`2503.13657`) | 是标注集/分类学，**不是在线检测器** |
  | 用户-系统意图漂移 | DriftHunter (ICDM'25) | 依赖闭集 intent/slot 本体，**agent 场景无此本体** |
- **预期使用者或下游场景**：多 agent 框架的运行时监控、协作失败的早期预警、agent 编排的自动熔断/重规划。

## 4. 【核心假设】

**核心假设：** 如果 将多 agent 交互的每一轮编码为一组可稳定标注的语义原子（role / goal-atom / tool-action / commitment / constraint），那么相对于 post-hoc 行为指标（role adherence、ASI 类复合分），逐轮累积原子级转移矩阵将在漂移发生的**那一步**给出可定位的检测信号（单步定位 F1 显著更高），因为行为指标是漂移后果的滞后聚合、无法对齐到轮次，而原子级转移保留了对齐到轮次的因果位置。

- **关键变量/处理**：语义原子本体的定义方式（原子粒度、标注协议）；转移矩阵的累积方式
- **预期方向**：单步定位 F1 提升；漂移的发生轮次可被提前预警
- **可能证伪的结果**（**任一命中即需重新评估**）：
  1. 语义原子的标注一致性 **Cohen's κ < 0.6** → 本体不成立，**方向终止**（第一道否决门槛，见 `experiment.md` P1）
  2. 漂移发生率**与随机基线无显著差异** → 现象不存在，无需检测器
  3. 逐轮转移**相对"只看相邻两轮"无增益** → 与 DriftHunter 犯同一个错误（见 §7 教训 4），方法层不成立
- **最小验证实验**：见 `experiment.md` 的 P1 探针（标注一致性门槛实验）

## 5. 研究问题

1. **RQ1**：agent 交互轮次上，能否定义一套稳定可标注的语义原子本体？（标注一致性门槛）
2. **RQ2**：agent 之间的语义漂移是否显著存在？发生率、在哪些框架/拓扑/任务类型下最高？
3. **RQ3**：漂移能否**仅从可观测信道**（不看人工标签）检出？弱监督上界是多少？

### 由此得出的定位结论（**必读**）

1. **不能做"DriftHunter 的 agent 版"**。问题层被 MAST 命名，方法层被 Spectral Dynamics 逼近，直接迁移会被审稿人判为"换场景"。
2. **差异化必须落在两点**：
   - **(a) 语义单位的定义**：把 slot 重定义为 agent 可观测原子（role / goal-atom / tool-action / commitment / constraint）——**目前无人做**；
   - **(b) 单步在线跳变信号**：现有工作全是 post-hoc 聚合或拓扑谱分析，**无人做逐轮语义状态的在线可微检测**。
3. **教训（来自本组对 DriftHunter 的批评，见 `001/drifthunter-and-webagent-survey-2026.md`）**：
   - 教训 4：必须内置「**只看相邻两轮**」的强基线，否则"累积是否必要"永远无法证明；
   - 教训 1：**不要用人工合成的退化数据**（DriftHunter 的随机拼接导致任务自我简化）。本 idea 的自建轨迹必须保证漂移是**语义层**的、而非表层话题变化。

## 8. 实验方案概览

> 详细探针设计见 `experiment.md`。**探针三问按顺序执行，前一个不过则不做下一个。**

- **方法/特征/模型**：分两阶段——① 探针阶段（**只验证现象，不做方法**）；② 方法阶段（仅在探针通过后启动）
- **基线**：至少两类——(i) post-hoc 行为指标（role adherence、ASI 类复合分）；(ii) **相邻轮强基线**（对应 §7 教训 4）
- **主要指标**：
  - 探针 P1：标注一致性 **Cohen's κ**
  - 探针 P2：漂移发生率 vs 随机基线（显著性检验）
  - 探针 P3 / 方法期：**单步定位 F1**（漂移发生在哪一轮）
- **次要指标**：预警提前量（轮数）、误报率、跨框架/跨拓扑的稳定性
- **消融或对照**：原子粒度消融；有/无跨轮累积；不同 agent 拓扑（星型/链型/全连）
- **预期资源与时间**：见 `experiment.md` §资源（**明确：探针阶段不需要多卡服务器**）
- **成功标准**：P1 κ ≥ 0.6 且 P2 显著且 P3 单步 F1 高于基线
- **停止条件**：P1 κ < 0.6 → 标记 `archived`，归档原因写入 §11，**不删除**

## 9. 风险与限制

- **数据风险**：无现成带漂移标签的 agent 轨迹集，需自建；自建轨迹的**生态效度**可能被质疑（模拟 ≠ 真实部署）
- **方法风险**：**核心风险是"换场景"指控**——若不能把贡献锚定在语义本体 + 单步信号上，会被判为 incremental
- **评估风险**：LLM-as-judge 不可靠（一致率约 85%，存在家族自偏好偏差，见 `001` 报告 §3.4）；**必须用人工标注做锚**，不能用 LLM 判自己
- **数据泄漏风险**：若用 LLM 生成轨迹又用同类 LLM 标注，存在自洽污染，需**交叉模型/人工抽检**
- **资源风险**：**探针阶段租多卡服务器属过度配置**（见 §10）
- **伦理、公平性或隐私风险**：低（公开框架 + 自生成数据）；若后续接入真实系统日志需重新评估
