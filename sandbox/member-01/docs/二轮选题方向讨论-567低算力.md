# 二轮选题方向讨论：05 / 06 / 07 低算力方向

> 本文用于组内二轮选题讨论，不代表已经立项的 Idea，也不替代正式的 `ideas/NNN-short-name-idea/` 文档。  
> 整理人：@member-01  
> 参考材料：[KDD2025低算力选题汇总报告.docx](./KDD2025低算力选题汇总报告.docx)

## 1. 讨论背景

根据《KDD 2025 教程低算力选题调研报告》，目前我们对以下三个方向更感兴趣：

- **05：时间序列异常检测（TSAD）**
- **06：数据异质性建模与可信机器学习**
- **07：频域深度学习时间序列**

三个方向都符合当前的低算力约束，但研究性质不同：

- 05 更偏向**评测、基准、公平性和无监督检测器选择**；
- 06 更偏向**数据诊断、分布偏移、误差切片和可信机器学习**；
- 07 更偏向**模型方法、频域表示和效率—精度权衡**。

因此，二轮讨论不只是比较“哪个方向更容易跑起来”，还要比较：

1. 是否能形成清晰、可证伪的研究问题；
2. 是否能在 CPU 或单张消费级 GPU 上完成完整实验；
3. 是否有公开数据和可复现基线；
4. 是否存在足够明确的创新切口；
5. 是否适合团队成员分工并在一年内形成投稿成果。

## 2. 三个方向的快速比较

| 编号 | 方向 | 主要研究对象 | 典型算力 | 数据与基线 | 报告中的可行度 | 初步判断 |
|---|---|---|---|---|---|---|
| 05 | 时间序列异常检测 | 无监督检测器、评测协议、内部指标、异常定位 | CPU；小深度模型可单卡 | TSB-UAD、TimeEval、UCR、TimeSeAD；经典方法和小型重建模型较多 | 高 | 最适合作为稳妥的评测/基准主线 |
| 06 | 数据异质性可信 ML | 子群发现、误差切片、分布偏移归因、鲁棒性 | 主要为 CPU；表格模型即可 | WhyShift、WILDS、UCI、Adult/ACS/金融等表格数据 | 中 | 研究问题有价值，但需要较强的问题抽象和方法设计 |
| 07 | 频域深度学习时间序列 | Fourier/Wavelet/DCT 表示、频域模块、预测/检测/分类 | 单卡；标准中小模型 | ETT、electricity、traffic、weather 等公开数据 | 中 | 工程实现直接，但需要避开“再做一个频域模块”的同质化 |

## 3. 方向 05：时间序列异常检测

### 3.1 方向概述

时间序列异常检测面向网络安全、金融、医疗、运维等场景，主要方法包括：

- 统计和经典无监督方法：LOF、Isolation Forest 等；
- 重建或预测模型：AutoEncoder、VAE、Anomaly Transformer、TranAD；
- Discord/Matrix Profile 方法：STAMP、STOMP、SCRIMP、STUMP；
- 基准与评测协议：TSB-UAD、TimeEval、TimeSeAD、UCR anomaly archive。

报告认为该方向整体属于低算力方向：经典方法 CPU 即可运行，深度检测器通常是百万参数规模的小模型，不依赖大规模预训练。

### 3.2 值得讨论的切口

#### 方向 05-A：无 ground-truth 时的检测器自动选择

**核心问题：** 在真实场景中，异常标签通常不完整或不可靠。没有 ground-truth 时，怎样根据数据本身选择更可能有效的检测器？

可研究内容：

- 比较不同内部指标与最终检测效果的一致性；
- 研究数据特征、异常稀疏度、周期性与检测器选择的关系；
- 构造一个面向无标签场景的 detector selection benchmark；
- 提出或组合一个可解释的内部评价指标。

优点：

- 与低算力约束高度匹配；
- 能复用成熟数据集和大量现有基线；
- 比单纯提出一个新检测器更容易形成公平、系统的研究问题。

风险：

- 基准复现和数据清洗工作量较大；
- “内部指标”和“真实效果”的关系需要严格设计，不能只做相关系数汇总；
- 需要避免只成为一篇实验报告，最好形成选择协议或可泛化的选择方法。

#### 方向 05-B：统一公平基准下的 TSAD 复现与偏差分析

**核心问题：** 不同论文使用不同数据预处理、指标、窗口和阈值设定，导致方法排名可能不稳定。统一协议后，经典方法和深度方法的真实差异是什么？

可研究内容：

- 统一数据切分、预处理、阈值和检测延迟计算；
- 对经典方法、Matrix Profile 方法和小型深度模型进行比较；
- 分析不同异常类型、异常比例、序列长度下的性能变化；
- 报告方法对随机种子、窗口长度和阈值策略的敏感性。

优点：

- 结果可解释，复现价值明确；
- 适合 Datasets & Benchmarks 或 Applied Data Science 方向；
- 对算力要求低。

风险：

- 需要把“公平性”落实成严格协议，而不是简单增加实验表格；
- 公开基准已有一定积累，创新点需要落在新的诊断维度或选择机制上。

#### 方向 05-C：流式 Matrix Profile / Discord 检测

**核心问题：** 在流式数据中，如何在准确率、检测延迟和 CPU 成本之间取得更好的平衡？

可研究内容：

- 面向在线数据的增量式 discord 更新；
- 不同窗口和采样策略对检测延迟的影响；
- 合成流数据与真实数据上的速度—准确率曲线；
- 资源受限条件下的早停或候选筛选。

该方向的优点是问题边界清楚、CPU 友好；但需要较强的算法实现能力，且应先确认相近的在线 Matrix Profile 工作，避免重复已有增量算法。

## 4. 方向 06：数据异质性与可信机器学习

### 4.1 方向概述

该方向不把平均准确率作为唯一目标，而是研究数据集内部的子群、不同生成过程和分布偏移如何影响模型可靠性。主要概念包括：

- 数据异质性建模；
- 子群发现与误差切片；
- `X-shift` 与 `Y|X-shift` 的分布偏移归因；
- DRO、IRM、HRM 等鲁棒学习方法；
- 面向医疗、金融和表格数据的可信评测。

报告指出，该方向主要使用统计方法、树模型、线性模型、GMM 和小型神经组件，公开表格数据通常 CPU 即可完成。

### 4.2 值得讨论的切口

#### 方向 06-A：面向 `Y|X-shift` 的误差切片发现与诊断

**核心问题：** 当训练集和测试集的条件分布发生变化时，哪些可解释子群会产生系统性错误？能否同时发现错误切片并判断其属于哪类分布偏移？

可研究内容：

- 在 WhyShift、Adult、ACS、Bank Account Fraud、Taxi 等数据上构造偏移场景；
- 比较回归树切片、聚类、GMM、Domino 或流形紧致度方法；
- 输出“人可以理解的失败规则”，例如某类地区、收入区间或业务条件；
- 将错误切片与 `X-shift` / `Y|X-shift` 归因结合起来。

优点：

- 问题有可信机器学习和数据中心 AI 的背景；
- 表格数据便于快速迭代；
- 输出可以从“模型分数”扩展为可解释诊断工具。

风险：

- 需要较扎实的分布偏移、统计和因果直觉；
- 偏移场景如何构造会显著影响结论；
- 如果只是把已有切片方法组合起来，方法创新可能不足。

#### 方向 06-B：子群发现驱动的重加权

**核心问题：** 是否可以先发现容易失败或代表性不足的子群，再用轻量重加权改善模型在偏移测试集上的表现？

可研究内容：

- 比较 group balancing、DRO、IRM、普通重采样和不加权基线；
- 研究不同子群发现错误对泛化和公平性的影响；
- 在医疗或金融表格数据上验证方法的稳定性；
- 同时报告平均性能、最差子群性能和校准误差。

该方向实现成本较低，但需要找到明确的新数据偏移类型或新的诊断—重加权闭环，否则容易变成已有鲁棒学习方法的复现。

#### 方向 06-C：表格模型主动评测与数据污染诊断

**核心问题：** 在 LLM 参与表格任务或自动生成数据的场景下，如何发现数据污染、难例和模型脆弱子群？

可研究内容：

- 用 API 生成难例、反事实问题或演化问题；
- 构造表格分类/回归任务的主动评测协议；
- 结合误差切片报告模型在不同子群上的失效模式；
- 比较人工问题、随机扰动和 LLM 生成问题的评测覆盖度。

该方向能连接数据异质性与当前的 LLM 评测热点，但 API 成本、问题质量和评测协议可靠性需要提前控制。

## 5. 方向 07：频域深度学习时间序列

### 5.1 方向概述

该方向把 DFT、DWT、DCT 等变换与 RNN、CNN、TCN、MLP 或 Transformer 结合，用于预测、异常检测、分类和插补。代表性方法包括 FEDformer、TimesNet、FiLM、FAN、ATFN 和 TFAD。

报告认为代表模型一般是百万参数级的中小模型，在 ETT、electricity、traffic、weather 等数据集上可以单卡复现，不依赖大规模预训练。

### 5.2 值得讨论的切口

#### 方向 07-A：频域方法在小样本和低资源场景下的有效性边界

**核心问题：** 频域表示是否真的在小样本、短序列、噪声较大或周期变化的数据上更有优势？优势来自频域变换本身，还是来自模型规模、窗口或调参差异？

可研究内容：

- 与 Linear、DLinear、MLP、TCN 等强基线进行严格比较；
- 控制模型参数量、训练预算、输入窗口和调参预算；
- 按周期性、噪声水平、样本量和预测跨度做分层分析；
- 报告精度、训练时间、推理延迟和显存占用。

这是 07 方向较稳妥的切入方式，因为重点从“提出一个新模块”转为回答频域方法何时有效。

#### 方向 07-B：频域方法的效率—精度—可解释性基准

**核心问题：** 不同频域变换和频域模块带来的收益，能否用统一资源预算和频谱分析解释？

可研究内容：

- 比较 Fourier、Wavelet、DCT 和不使用频域变换的模型；
- 分析保留频率、频率截断和多尺度分解的影响；
- 记录训练时间、推理延迟、参数量和内存；
- 观察频域特征与真实周期、异常模式之间的对应关系。

优点是实验可控、低算力；风险是已有频域模块较多，必须把“统一资源预算”和“可解释的适用边界”做实。

#### 方向 07-C：频域增强的时间序列异常检测

**核心问题：** 频域特征是否能帮助异常检测器识别周期扰动、局部突变或频率漂移？

可研究内容：

- 将轻量频域特征加入经典异常检测器或小型重建模型；
- 在不同异常类型下比较时域、频域和时频联合表示；
- 与 05 的 TSAD 基准和公平评测协议结合；
- 分析频域模块在不同异常密度和采样频率下的失败案例。

该方向最适合与 05 形成交叉，而不是单独追求复杂网络结构。这样可以把 07 的方法问题放到 05 的统一评测框架中验证。

## 6. 三个方向的横向判断

### 6.1 按研究风险比较

| 方向 | 主要风险 | 风险等级 | 需要提前验证的事项 |
|---|---|---:|---|
| 05 | 基准复现工作量大、已有基准较多 | 低—中 | 数据是否可获得；指标、阈值和标签协议能否统一 |
| 06 | 问题抽象和方法创新要求较高 | 中 | 偏移构造是否合理；误差切片能否得到稳定、可解释结果 |
| 07 | 频域模块同质化、有效性可能依赖数据集 | 中 | 强基线是否充分；频域收益是否跨数据集稳定 |

### 6.2 按团队协作比较

| 方向 | 可拆分的工作包 |
|---|---|
| 05 | 数据集与协议、经典基线、深度基线、内部指标、效率分析 |
| 06 | 偏移场景构造、切片算法、误差诊断、重加权方法、垂直领域数据 |
| 07 | 频域变换实现、预测/检测模型、强基线、资源统计、频谱可解释性 |

05 最容易拆成并行工作包；06 需要较强的统一问题定义；07 的代码模块容易拆分，但实验结论必须由同一套资源和数据协议约束。

### 6.3 按成果形态比较

- **05：** 最自然的成果形态是统一基准、评测协议、检测器选择方法或公平性分析。
- **06：** 最自然的成果形态是误差切片/分布偏移诊断工具，以及在医疗或金融表格数据上的可信实证。
- **07：** 最自然的成果形态是轻量频域方法、适用边界分析或效率—精度基准。

## 7. 当前建议：先以 05 为主线，06 和 07 做平行探针

基于报告给出的算力、数据和一年可行度判断，当前建议不是立即三选一，而是采用：

> **05 作为主线候选，06 作为可信机器学习平行候选，07 作为与 05 交叉的轻量方法候选。**

理由如下：

1. 05 的公开数据、经典基线和评价对象最明确，最容易在短周期内形成可比较结果；
2. 05 的“无标签检测器选择”和“公平基准”能够直接形成可证伪的问题，而不是只比较模型分数；
3. 06 具有更强的问题价值，但需要先确认我们是否具备足够的分布偏移和统计建模能力；
4. 07 单独做新模块存在同质化风险，与 05 结合后可以通过 TSAD 统一基准检验频域方法的真实收益；
5. 三个方向都能使用 CPU/单卡完成，不会因为算力约束过早淘汰候选方向。

### 建议的候选组合

#### 组合 A：TSAD 基准 + 检测器自动选择（优先验证）

- 主问题：没有 ground-truth 时，哪些内部指标能可靠选择异常检测器？
- 主要数据：TSB-UAD、TimeEval、UCR 或 TimeSeAD；
- 最小实验：先选 5–8 个检测器、3–5 个内部指标、多个数据集和统一评价协议；
- 主要结果：内部指标与真实检测性能的一致性、跨数据集泛化和选择后性能。

#### 组合 B：TSAD 公平基准 + 频域增强（05 × 07）

- 主问题：频域表示相对于强时域基线在哪些异常类型和数据条件下有效？
- 最小实验：经典方法、小型重建模型、轻量频域模型和 Linear/DLinear 强基线；
- 主要结果：检测性能、资源消耗、异常类型分层结果和失败案例。

#### 组合 C：误差切片 + 分布偏移诊断（06）

- 主问题：能否发现与 `Y|X-shift` 相关的稳定失败子群，并输出可解释诊断规则？
- 最小实验：一个表格数据基准、两类偏移、两种切片方法、一个简单重加权基线；
- 主要结果：切片稳定性、最差子群性能、偏移归因准确性和解释质量。

## 8. 建议的二轮讨论问题

组内讨论时建议优先回答以下问题：

1. 我们更希望产出**基准/评测型成果**，还是**轻量方法型成果**？
2. 是否愿意承担 05 方向的数据清洗、统一协议和大规模复现实验？
3. 对 06 方向中的分布偏移、子群和误差切片是否有足够兴趣和知识储备？
4. 07 方向是否接受“不以新网络模块为目标”，而是研究频域方法的适用边界？
5. 是否有明确的应用数据来源，例如金融、医疗、设备运维或网络流量？
6. 团队能否承担 API 成本，还是希望全部实验保持 CPU/本地单卡？
7. 第一阶段是否先做一个 2–4 周的可行性探针，而不是直接确定正式编号？

## 9. 建议的 2–4 周可行性探针

### 第 1 周：统一环境和最小数据集

- 选择一个 05 数据集、一个 06 表格数据集和一个 07 时间序列预测/检测数据集；
- 固定 Python、依赖、随机种子、数据版本和评价指标；
- 建立统一结果表，记录运行时间、内存、参数量和主要指标。

### 第 2 周：跑通强基线

- 05：Isolation Forest、LOF、Matrix Profile 或一个小型重建模型；
- 06：Logistic Regression/XGBoost + 一个简单切片或偏移诊断方法；
- 07：Linear/DLinear + 一个频域模型；
- 不在此阶段加入复杂新模块。

### 第 3 周：验证候选问题

- 05：测试内部指标是否能预测检测器相对表现；
- 06：测试误差切片是否稳定且可解释；
- 07：测试频域方法收益是否跨数据条件存在；
- 对每个方向记录失败案例，而不是只记录最好结果。

### 第 4 周：做方向决策

建议用以下标准做 go/no-go：

- 问题是否可以用一句话写成可证伪假设；
- 最小实验是否能在一周内重复运行；
- 结果是否不依赖单一数据集或单一随机种子；
- 是否能说明相对已有工作的新增价值；
- 是否有成员愿意负责后续 3 个月的主线推进。

探针完成后，若某个方向满足条件，再从 `ideas/000-template/` 建立正式 Idea，并在 `PROGRESS.md` 登记编号。当前阶段不建议直接把 05、06、07 分别登记成三个正式 Idea，以免重复建设和过早分散资源。

## 10. 结论

05、06、07 都是符合低算力约束的候选方向，但优先级可以暂时区分：

1. **05 时间序列异常检测：** 最适合先做，优先验证基准公平性和无标签检测器选择；
2. **06 数据异质性可信 ML：** 研究价值较强，适合作为需要更深入讨论的问题型候选；
3. **07 频域深度学习时间序列：** 不建议直接做“新频域模块”，优先作为 05 的交叉方法或做效率—精度边界分析。
